**Lo que dijo la profesora en la clase del 10/10** ([resumen](/final/clase-memoria/)):
- la **segmentación entra**;
- no pedirá mucha conversión decimal ↔ binario (dará equivalencias), y como mucho hexadecimal;
- **todo en base 2**;
- si no mencionan bits de validez, la PTE solo guarda el frame.

### Las 13 trampas más probables

1. **Contar o no los fallos iniciales** en reemplazo. Decláralo.
2. **Clock:** el puntero queda **después** del frame reemplazado, y un acierto **no mueve** el puntero.
3. **Belady:** FIFO y Clock pueden tenerla; **LRU y OPT nunca**.
4. **Fija + global es imposible.**
5. «turn tiene un solo valor» **no prueba exclusión mutua**: prueba ausencia de deadlock.
6. **`sem_wait` vs `sem_trywait`:** «si no hay silla, se va» exige `trywait`.
7. **`sem_getvalue` + `wait`** es check-then-act: está **mal**.
8. **Mutex con dueño:** no lo puede soltar otro hilo. Semáforo **sin dueño**: sí.
9. **memcheck** reporta el valor no inicializado **donde se usa** (if, printf), no donde se declara, y **no** ve desbordes del stack.
10. **`malloc(strlen(s))`** sin el +1 para el `'\0'`.
11. **Offset:** en paginación se **concatena**; en segmentación se **suma** (y se compara con el límite: `offset < longitud`).
12. **Traducir sin mirar la tabla:** primero la página, luego su entrada (¿Valid = 1?), luego la física. La profesora cometió este error en vivo con 2221.
13. **EAT:** ¿la TLB se consulta siempre? ¿La tabla es de 1 o de k niveles? Escribe el modelo.

## Código 1 (3 pts) · La barbería que cierra

> Una barbería tiene **3 barberos**, **4 sillas de espera** y recibe **200 clientes** (hilos).
> - Un cliente que no encuentra silla de espera **se va**.
> - Cada cliente debe ser atendido por **un barbero concreto** y saber cuál es.
> - Un barbero sin clientes **duerme**, y nunca atiende a dos a la vez.
> - Cuando los 200 clientes terminaron (se atendieron o se fueron), la barbería **cierra**: **todos** los barberos deben salir de su bucle y `main` debe poder hacer `pthread_join` de cada uno. El programa no puede quedar colgado.
>
> Escribe `barbero()`, `cliente()` y el cierre en `main` usando **solo semáforos POSIX** y variables compartidas.

<Solucion titulo="Solución (probada: 3 corridas, 200/200 clientes, los 3 barberos terminaron siempre)">

La base es el **panel** de las diapositivas, ya corregido ([barbero § N barberos](/final/deadlock/barbero/#n-barberos-diap-4247)). Lo difícil es el **cierre**: un barbero puede estar dormido en **dos** lugares distintos, `wait(write_panel)` o `wait(client_seat[id])`, y hay que despertarlo en cualquiera de los dos.

```c
sem_t seats, write_panel, read_panel, client_seat[NB], hair_cut[NB];
int panel;
volatile int cerrado = 0;

void *barbero(void *a) {
    int id = (int)(long)a;
    for (;;) {
        sem_wait(&write_panel);
        if (cerrado) { sem_post(&write_panel); break; }   // pasa el «testigo» al siguiente barbero
        panel = id;
        sem_post(&read_panel);
        sem_wait(&client_seat[id]);
        if (cerrado) { sem_post(&write_panel); break; }   // lo despertó main, no un cliente
        cut_shave();
        sem_post(&hair_cut[id]);
    }
    return NULL;
}

void *cliente(void *a) {
    if (sem_trywait(&seats) == 0) {
        sem_wait(&read_panel);
        int my = panel;
        sem_post(&write_panel);
        sem_post(&seats);
        sem_post(&client_seat[my]);
        sem_wait(&hair_cut[my]);
    } else leaves();
    return NULL;
}

/* main, después de pthread_join de los 200 clientes: */
cerrado = 1;
for (int i = 0; i < NB; i++) sem_post(&client_seat[i]);   // despierta al que publicó su id
for (int i = 0; i < NB; i++) pthread_join(b[i], NULL);
```

**Por qué termina:**
- Cuando ya no quedan clientes, **exactamente un** barbero publicó su id y duerme en `client_seat[id]`. Ese tiene `write_panel` «tomado» porque ningún cliente lo leyó. Los otros dos duermen en `wait(write_panel)`.
- `main` hace `post` a **todos** los `client_seat`. El que publicó despierta, ve `cerrado` y **devuelve** `write_panel`.
- Eso despierta a otro barbero en `wait(write_panel)`, que ve `cerrado`, devuelve el testigo y sale. Y así en **cadena** hasta que salen todos.
- Los `post` sobrantes en los `client_seat` de los barberos que no publicaron no hacen daño: esos barberos salen por el primer `if` y nunca llegan a esperar en su `client_seat`.

**Ejecución de prueba:**

```text
cerrado: atendidos=200 se_fueron=0 (total 200); cortes por barbero = 63 66 71; los 3 barberos terminaron
cerrado: atendidos=200 se_fueron=0 (total 200); cortes por barbero = 65 68 67; los 3 barberos terminaron
cerrado: atendidos=200 se_fueron=0 (total 200); cortes por barbero = 68 63 69; los 3 barberos terminaron
```

Además, un `assert` comprobó en cada corte que ningún barbero atendía a dos clientes a la vez.

**Errores típicos que restan puntos:**
- **Cerrar con `pthread_cancel`:** puede matar a un barbero en medio de un corte.
- **Hacer `post` solo a `write_panel`:** el barbero dormido en `client_seat` nunca despierta y el `join` **cuelga**.
- **Revisar `cerrado` solo al inicio del bucle:** mismo problema.
- **Usar `sem_wait(&seats)`:** el cliente no se iría.

**Pauta (3 pts):** 1 por el panel correcto (cada cliente con su barbero) · 0.5 por `trywait` y la liberación de la silla · 0.5 por el aviso de fin de corte · 1 por el cierre sin colgarse.

</Solucion>

```c
nodo *nuevo(const char *nombre, int nota) {
    nodo *n = malloc(sizeof(nodo));
    n->nombre = malloc(strlen(nombre) + 1);           // #1
    strcpy(n->nombre, nombre);
    n->nota = nota;
    n->sig = NULL;                                     // #6
    return n;
}

void liberar(nodo *l) {
    while (l != NULL) {
        nodo *sig = l->sig;                            // #4: guardar ANTES de liberar
        free(l->nombre);                               // #5
        free(l);
        l = sig;
    }
}

/* en main: */
int *tmp = realloc(notas, 3 * sizeof(int));            // #7
if (tmp == NULL) { free(notas); liberar(l); return 1; }
notas = tmp;
notas[2] = (notas[0] + notas[1]) / 2;                  // #3
```

## Análisis 1 (3 pts) · Clock mejorado con escrituras

> **4 frames** vacíos y Clock **mejorado** (bits u y m, algoritmo de Stallings fig. 8.17).
> - Al cargar: u = 1, y m = 1 si la referencia es de escritura.
> - El puntero queda en el frame **siguiente** al reemplazado.
> - Referencias (`w` = escritura, `r` = lectura): `Aw Br Cr Dw Ar Er Bw Fr Cr Aw Gr Dr Hr Cw`.
>
> Da el contenido final con sus bits, el número de fallos y el número de **escrituras a disco** (víctimas con m = 1).

<Solucion titulo="Solución (verificada con un simulador del algoritmo)">

**Notación:** `*` = u en 1, `m` = modificada, `·` = frame vacío.

| Ref | Resultado | f0 | f1 | f2 | f3 | Puntero |
| --- | --- | --- | --- | --- | --- | :-: |
| Aw | fallo | A\*m | · | · | · | 1 |
| Br | fallo | A\*m | B\* | · | · | 2 |
| Cr | fallo | A\*m | B\* | C\* | · | 3 |
| Dw | fallo | A\*m | B\* | C\* | D\*m | 0 |
| Ar | acierto | A\*m | B\* | C\* | D\*m | 0 |
| Er | fallo, sale **B** | Am | E\* | C | Dm | 2 |
| Bw | fallo, sale **C** | Am | E\* | B\*m | Dm | 3 |
| Fr | fallo, sale **D** ✍ | Am | E\* | B\*m | F\* | 0 |
| Cr | fallo, sale **A** ✍ | C\* | E\* | B\*m | F\* | 1 |
| Aw | fallo, sale **E** | C | A\*m | Bm | F | 2 |
| Gr | fallo, sale **F** | C | A\*m | Bm | G\* | 0 |
| Dr | fallo, sale **C** | D\* | A\*m | Bm | G\* | 1 |
| Hr | fallo, sale **B** ✍ | D\* | Am | H\* | G\* | 3 |
| Cw | fallo, sale **A** ✍ | D | C\*m | H\* | G | 2 |

**Paso clave (Cw):** ninguna página es (0,0). El barrido 2 apaga G y D y encuentra A = (0,1): sale **A**, que estaba modificada, así que hay una escritura a disco.

**Paso clave (Er):** los 4 tenían u = 1, así que no hay ni (0,0) ni (0,1).
1. El **barrido 2** apaga todos los u mientras busca (0,1), y no encuentra.
2. Se **repite el barrido 1** desde el puntero (f0): A es (0,1), no sirve; B es (0,0): **sale B**. A tenía prioridad para quedarse porque está modificada.

**Respuesta:**
- **Estado final:** f0 = D (u = 0), f1 = **C (u = 1, m = 1)**, f2 = H (u = 1), f3 = G (u = 0). El puntero queda en el frame 2.
- **13 fallos** de 14 referencias.
- **4 escrituras a disco** (✍): las víctimas modificadas fueron D, A, B y otra vez A (la que se había reescrito con `Aw`).

Con LRU, la misma cadena da también **13 fallos y 4 escrituras**. Clock mejorado no siempre gana en fallos; su ventaja es que **prefiere** víctimas limpias cuando las hay, y lo logra con 2 bits por frame en vez de marcas de tiempo.

**Pauta:** 1 por la tabla hasta Er (el paso difícil) · 1 por el estado final · 1 por fallos y escrituras con la convención declarada.

</Solucion>

## Análisis 2 (3 pts) · EAT con fallos de página

> - Memoria principal: **100 ns**. TLB: **2 ns** (se consulta siempre). Tablas de **2 niveles**.
> - Tasa de aciertos de la TLB: **95 %**.
> - Atender un page fault cuesta **8 ms**, o **20 ms** si la víctima está sucia, lo que pasa en el **30 %** de los fallos.
>
> a) EAT si la probabilidad de fallo por acceso es $p = 10^{-6}$.
> b) ¿Qué $p$ máxima permite que el EAT sea como mucho un **10 %** mayor que sin fallos?

<Solucion titulo="Solución">

**Sin fallos:**
$$
\text{EAT}_{mem} = 2 + 100 + 0.05 \cdot (2 \cdot 100) = 112\ \text{ns}
$$

**Costo medio de un fallo:**
$$
0.7 \cdot 8\ \text{ms} + 0.3 \cdot 20\ \text{ms} = 11.6\ \text{ms} = 11\,600\,000\ \text{ns}
$$

**a)**
$$
\text{EAT} = (1-p)\cdot 112 + p \cdot 11\,600\,000 \approx 112 + 11.6 = \mathbf{123.6\ ns}
$$
Un fallo cada **millón** de accesos ya agrega un 10 % de tiempo.

**b)**
$$
(1-p)\cdot 112 + p \cdot 11\,600\,000 \le 1.1 \cdot 112 = 123.2
\;\Rightarrow\;
p \le \frac{11.2}{11\,600\,000 - 112} \approx \mathbf{9.66 \times 10^{-7}}
$$
Es decir, como mucho **un fallo cada ~1 035 704 accesos**.

**Lectura:** el disco es tan lento que la tasa de fallos tiene que ser **ínfima**. Por eso importan tanto la localidad, el working set y no caer en thrashing. Las páginas sucias encarecen el fallo (de 8 a 20 ms); eso es lo que motiva el *precleaning* y el Clock mejorado.

**Pauta:** 1 por EAT sin fallos · 1 por (a) · 1 por (b).

</Solucion>

## Análisis 3 (3 pts) · Tanenbaum con un bug sutil

> En `tanen-sem.c`, alguien «optimiza» `release_forks` y deja **solo** `test_forks(LEFT)`, borrando `test_forks(RIGHT)`. Con N = 5:
> a) ¿Puede haber deadlock?
> b) ¿Qué propiedad se rompe? Da una traza corta.
> c) Si cada filósofo come un número **finito** de veces, ¿qué le pasa al programa?

<Solucion titulo="Solución (verificada recorriendo todos los estados con N = 5)">

**a) No hay deadlock.** Recorrí todos los estados (341) y en ninguno quedan todos bloqueados: siempre hay alguno que puede pensar, ponerse hambriento o comer.

**b) Se rompe el progreso: un filósofo puede quedar esperando con los tenedores libres.** Traza de 4 pasos (en el código, `LEFT = (id + 1) % N` y `RIGHT = (id + N − 1) % N`):

| # | Acción | Estados (F0…F4) |
| - | --- | --- |
| 1 | F0 `take_forks`: H; nadie come, así que pasa a **E** | E T T T T |
| 2 | F0 hace `sem_wait` y pasa (come) | E T T T T |
| 3 | F4 `take_forks`: H, pero su vecino F0 (= LEFT de F4) **come**, así que espera | E T T T **H** |
| 4 | F0 `release_forks`: T y prueba **solo** `test_forks(LEFT de F0 = F1)`. **Nadie prueba a F4** | T T T T **H** |

**Ahora F4 está hambriento, la mesa está vacía, y aun así duerme en `sem_wait(&philosopher[4])`.** Solo lo puede despertar su otro vecino (F3) cuando coma y libere, porque al hacerlo prueba a su LEFT, que es F4. Es un **despertar perdido**: la condición se cumplió, pero nadie se lo avisó.

En el algoritmo correcto (con las dos pruebas), el mismo recorrido de estados **no encuentra** ningún estado así.

**c) El programa puede quedar colgado para siempre.** Si F3 ya terminó sus porciones y no vuelve a comer, F4 no se despierta nunca, y `pthread_join` de F4 no retorna. No es un deadlock clásico (no hay espera circular por recursos): es **starvation por un aviso perdido**, que en la práctica se ve igual que un cuelgue.

**Pauta:** 1 por (a) bien justificada (no basta «no hay espera circular») · 1.5 por la traza · 0.5 por (c).

</Solucion>

## Extra (sin puntaje) · El costo real de las tablas de 4 niveles

> x86-64: direcciones virtuales de **48 bits**, páginas de 4 KB y PTE de 8 B. Un proceso usa **1 GB contiguo** de memoria virtual. ¿Cuánta memoria ocupan sus tablas de páginas? Compáralo con una tabla de un solo nivel.

<Solucion titulo="Solución">

- **Partes de la dirección:** offset de 12 bits y VPN de 36. Cada tabla ocupa 4 KB con 512 entradas, así que hay **9 bits por nivel** y $36/9 = 4$ niveles.
- **Páginas usadas:** 1 GB / 4 KB = 262 144 páginas.
- **Tablas por nivel:**
  - **Nivel 4** (PTE): 262 144 / 512 = **512 tablas**;
  - **nivel 3**: 512 entradas, que caben en **1 tabla**;
  - **nivel 2: 1 tabla**;
  - **nivel 1** (raíz): **1 tabla**.
- **Total:** 515 tablas × 4 KB ≈ **2.01 MB**.
- **Tabla de un solo nivel:** $2^{36}$ entradas × 8 B = $2^{39}$ B = **512 GiB** por proceso, imposible.

El multinivel solo crea las tablas de las regiones **usadas**: esa es toda la gracia.
